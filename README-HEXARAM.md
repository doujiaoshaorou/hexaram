## 使用

将 `Hexaram-0.3.0-win-x64.exe` 与旧版放在同一文件夹，保留原有 `user-data/archives/`，登录英雄联盟后启动。首次识别账号会自动读取旧版 JSON 归档并同步当前接口可取得的历史；旧归档只读保留。新归档位于 `hexaram-data/<大区>-<PUUID>.json`，新设置位于 `hexaram-config.yaml`，不会覆盖 RA 的设置。离线时显示最后成功加载的本人归档。

- **我的战绩**：本人账号、模式/日期/英雄筛选、累计与近期表现，直接使用 RA 战绩卡片与十人详情；近期好友/宿敌面板沿用 RA。
- **查询**：顶部搜索其他玩家，独立于本人归档。通过 RA 的 SGP 解析与映射获取海克斯记录，按原始索引推进分页，先过滤模式/英雄再取十条。
- **对局**：沿用 RA 客户端监听与会话同步、渐进加载的双方阵容、玩家历史。海克斯队列使用海克斯评级；强化推荐随本人的英雄变化。选人时只能展示客户端已提供的身份，进游戏后补全敌方。
- **英雄**：OP.GG 普通海克斯英雄梯队；点击英雄查看强化推荐。不再显示排位分路、排位分段或排位构筑。
- **英雄表现 → 我的海克斯**：自己的强化场数、胜负、胜率、同英雄基准差值、使用过的英雄及英雄对应胜率；可搜索、排序、设最少场数，点英雄过滤，点“查看选择过的对局”回看对应明细。

## 数据口径

普通海克斯 2400、巅峰赛 2410、经典版 2450 分开统计，“全部海克斯”才合并。不纳入普通大乱斗 450、排位或人机。每场同一强化在多个槽位重复时只计算一次；同一场的多枚不同强化分别计算，因此各强化场数相加不等于总场数。

“胜率差”是选用某强化的实际胜率，减去按该强化使用英雄的场数加权的各英雄整体胜率。例如只在莉莉娅上使用某强化，就与莉莉娅整体胜率比较。差值是历史相关性，不能证明强化导致胜率提升；少于十场标为低样本。缺少胜负的记录不进入分母，缺少强化槽位的记录不伪造强化。

OP.GG 来源为 https://op.gg/zh-cn/lol/modes/aram-mayhem 。直接读取公开页面的结构化 JSON，不执行远端脚本。缓存一小时，失败不回退为排位数据；页面格式变化时显示不可用。页面提供梯队和 `performance` 评分，评分**不是胜率**，不将它伪装成百分比。个人胜率仅来自本人归档。此来源为普通海克斯；巅峰赛/经典版中的该评级只作普通海克斯参考，不宣称为这些变体的独立榜单。

实时近期数据优先从 SGP 最近 100 条原始记录中筛选当前海克斯模式，再取配置条数；网络失败时回退 LCU 可用窗口。因此他人的近期面板是可用近期样本，不是全生涯统计。按 RA 的换局/重连缓存失效机制刷新。

## 历史完整性

掌上英雄联盟的 1,537 场是用户提供的跨赛季汇总对照值，尚未获得对应全量逐场明细。2026-10-05 本机验证旧归档与新记录合并到 1,001 条，其中普通海克斯 951 场（479 胜、472 负）；另有巅峰赛及非海克斯原始记录。不能把原始总条数当海克斯场数。

同步最多检查 10,000 条，不在 1,000 条截断；遇空页、重复页或错误分别处理，逐页保存，按大区与对局 ID 去重合并。空页只表示当前可查询窗口结束，界面始终提示可能缺少更早记录。模式上线于 2025-10-23，但本机可取明细未覆盖早期全部历史。

## 开发与构建

应用源码在 `rank-analysis-app/`。需要 Node/npm、Rust stable MSVC、Windows C++ Build Tools 和 WebView2。

```powershell
cd rank-analysis-app
npm ci
npm run typecheck
npm test -- src/services/hexaram.spec.ts src/composables/useSessionSync.spec.ts src/composables/useMatchDetailPlayers.spec.ts
cargo test --manifest-path src-tauri/Cargo.toml --lib command::hexaram::tests
npm run tauri build -- --no-bundle
```

生成 `src-tauri/target/release/hexaram.exe`。上游更新入口已禁用，防止官方 RA 覆盖此衍生版本。开发工具与真实联调归档位于 `.tools/`，不可打包发布；不把用户记录、凭证或调试端口放入分发文件。正式构建不包含上游 debug 专用 MCP bridge。
