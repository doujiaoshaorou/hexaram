# 海克斯战绩本 · Hexaram

![WY 标志](rank-analysis-app/src/assets/wy-logo.svg)

面向国服海克斯大乱斗的个人战绩、强化统计与复盘工具。当前版本 **0.8.1**，Windows x64。

作者：[doujiaoshaorou](https://github.com/doujiaoshaorou)。使用 **GPT-6 Astra** 辅助二次开发。

## 开源来源

本项目基于 [wnzzer/Rank Analysis](https://github.com/wnzzer/rank-analysis) 二次开发，保留原 Vue 3 / Tauri 2 / Rust 架构、客户端连接、战绩卡片、十人详情及实时阵容能力。上游固定提交为 `5e9fe0c64233126e3a2c0dc0784dca18e1ddaf08`。保留上游 MIT 许可证与版权声明，详见 [LICENSE](LICENSE) 和 [第三方说明](THIRD_PARTY_NOTICES.md)。这是独立衍生项目，并非 RA 官方版本。

## 使用

下载发布附件 `Hexaram-0.8.1-win-x64.exe`，放在可写目录运行。需要 Windows WebView2；英雄联盟登录后自动连接并同步可取得的战绩。与客户端权限保持一致。旧版用户将新版放在原目录，保留 `user-data/archives/`；新归档写入 `hexaram-data/`，旧归档只读导入。

- **我的战绩**：固定本人身份，RA 双栏布局，近 20 场表现、好友/宿敌、累计场数/胜率/KDA/英雄数量。列表每页 10 场，直接点击 1–10 页查看最近 100 场；累计统计仍使用全部归档。点击“补齐本机历史”，从游戏日志的对局 ID 读取客户端完整详情并合并去重。
- **查询**：顶部搜索其他玩家；切换页面后恢复最近查询对象、筛选和页码。点击“× 关闭查询”清空查询对象与恢复缓存。结果缓存限本次运行，不与本人归档混用。左侧历史表现首批获取至多 100 场，可继续加载；接口边界不等于生涯全部。
- **英雄表现**：个人英雄统计和强化统计；查看选用强化的英雄、胜率、样本量以及相关对局。
- **对局**：实时双方阵容与近期海克斯战绩；选人期读取当前英雄及共享池，展示个人常用、高胜率和低胜率英雄。队友英雄需对方同意交换，程序不代选、代禁或自动交换。
- **英雄**：OP.GG 海克斯梯队，每行展示五枚本英雄推荐强化；点击英雄，纵向查看推荐评级、棱彩/黄金/白银、名称与说明。
- **设置**：匹配开关、个人英雄池推荐、标签、人物标记、数据同步、版本与来源说明。

## AI 复盘

MVP/SVP 保留 RA 的七维加权评分。AI 复盘采用六个维度：输出贡献、承伤与生存、参团与支援、海克斯与英雄适配、装备与阵容适配、海克斯与装备联动。数字依据由程序计算并展示；模型只生成解释和条件建议。装备和强化引用须核对实际持有者，资料不足时不判断具体收益。旧版“背锅/被连累”报告不再用于海斗。结构校验未通过时最多自动纠正一次，网络或服务错误不自动重试。

AI 支持 DeepSeek 和 DashScope（通义千问）。在常规设置选择服务商、填入对应 Key 并点击“保存 AI 配置”，立即生效；旧版已填写的 Key 会保留，但 DeepSeek 用户需选择 DeepSeek 后保存。模型可留空使用默认：DeepSeek 使用 deepseek-flash，通义千问根据分析任务选择模型。服务地址分别为 api.deepseek.com 与 dashscope.aliyuncs.com，Key 不能跨服务商使用。需要自己的 API Key，并消耗自己的额度；发行包不内置公共密钥。RA 官方构建使用作者在 GitHub Actions Secrets 中配置的 Key，开源源码与本项目不会继承。缺少 Key 时复盘窗口显示配置入口；未发送请求不能认定通义千问服务失效。Key 保存在本机配置中，不要上传该配置文件。点击 AI 分析时会向该服务发送相关对局数据；玩家备注默认不携带。常规查询、统计、OP.GG 推荐不需要 Key。

没有录像或操作时间线，AI 不能验证站位、技能命中或购买顺序；输出仅作统计复盘参考。当前客户端及 OP.GG 海斗资源说明可能与旧对局版本不同。强化说明按真实强化标识匹配，不通过复用图标猜测机制。

## 数据口径与限制

- 默认只统计正常对局；客户端标记提前结束的重开局不计入场数、胜负、KDA、英雄、强化与表现积分。原始记录保留，可勾选“显示重开局”查看。仅凭时长短不能判定重开。
- 普通海克斯 2400、巅峰赛 2410、经典版 2450 独立过滤；不把普通大乱斗、排位和人机计入个人海克斯统计。
- 原始记录总条数不等于海克斯场数。当前接口可能不返回早期历史，累计数字仅代表已归档明细。0.6.0 新增本机日志补录，已突破近期列表的 1,000 条窗口；没有留在本机日志中的比赛仍无法保证找全。累计计数不能替代逐场明细。
- OP.GG 来源是普通海克斯梯队，变体中仅作参考。梯队评分不是个人胜率。资源不可用时不伪造推荐，也不回退到排位榜。
- 海克斯胜率差与同英雄的历史基准加权比较，仅代表相关性；少于十场标为低样本。
- 对局页每位玩家的历史卡片默认显示 4 场，可设 1–20；不影响近 20 场摘要或全部归档。

## 构建

需要 Node.js、npm、Rust stable MSVC、Windows C++ Build Tools 和 WebView2。

```powershell
cd rank-analysis-app
npm ci
npm run typecheck
npm run tauri build -- --no-bundle
```

输出 `rank-analysis-app/src-tauri/target/release/hexaram.exe`。不要向构建过程注入个人 AI 密钥。公开仓库的 Windows 构建工作流可手动运行，生成可下载的构建附件。

DeepSeek 接入依据：[官方 API 文档](https://api-docs.deepseek.com/)。Git 已在本机 D:\Git 安装；本轮未创建远程仓库或上传 GitHub。

## 0.7.0 正常对局与累计表现积分

- 历史场数核对改为只读：自动按赛段归类正常对局、重开记录和各模式场数，不再要求手填掌盟数据。没有接入掌盟官方统计接口，不宣称自动核验掌盟账户。
- 我的战绩、查询、英雄表现和最近表现统一排除客户端标记的重开局；记录保留，默认列表隐藏，可手动显示并查看。
- 用 **WY 表现积分** 替代 0.6.0 的胜负估分。从 0 开始累积：胜利 +6、失败 +1；贡献 +0～6；RA 七维 MVP +4、SVP +2。贡献综合输出、有效承伤、支援、推塔与参团，不由胜率直接映射。
- 多项低贡献与高死亡条件同时成立时扣 8 分；缺少支援数据不重扣，不把单项低输出直接认定为胜负责任。重复同队只降低正积分，不减免负分。
- 卡片提供场均净积分、趋势及最近逐局加减分明细。总分受场数影响，是本项目可解释的积分规则，不是官方 MMR 或经验证的竞技实力估计。

具体计分公式、测试与限制见 [0.7.0 验证记录](VALIDATION-0.7.0.md)。

## 0.8.0 固定窗口评分与海斗玩法标签

- 以最近最多 200 场正常海斗的加权平均取代累计积分。胜率为主，队内贡献、MVP/SVP 和多项低贡献作修正；小样本向 1000 收缩，旧局滑出窗口。场数不会无限推高分数。该规则是项目估计，不代表官方 MMR 或排位段位。
- 评分卡显示胜负、贡献、荣誉、低贡献四项分解和逐局依据，各模式独立。重复同队降低样本证据权重，不断言组排。
- 移除积极参团、输出担当、承伤担当、多英雄体验四个默认标签，新增前排常客、奶盾偏好、救场奶盾、辅助低效局偏多、前排脱节局偏多、经济转输出。玩法需英雄定位与出装证据，低效需多项条件重复出现；自疗不等于队友治疗。
- 玩法标签最多取 200 场，至少 30 场才判断；近期胜负与魔怔人规则仍用 20 场，最近表现卡仍显示 20 场。已有自定义规则保留。
- 详细公式、阈值与测试见 [0.8.0 验证记录](VALIDATION-0.8.0.md)。上文 0.7.0 累计积分仅为旧版变更记录。
