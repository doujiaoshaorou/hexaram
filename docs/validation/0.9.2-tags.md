# 0.9.2 标签规则与编辑器验证

日期：2026-10-11。

## 变更范围

- 25 个内置标签与自定义标签共用条件树；按海克斯模式分别取样，排除重开。
- 长期窗口 200 场、近期窗口 50 场；最低有效样本独立配置。
- 新增英雄主类型、全能高手、输出、承伤、经济、综合 KDA、MVP/SVP 等规则。
- 编辑器覆盖单局 AND / 候选组 OR、有效比例、最低命中场数、总量 KDA、类型分布及胜率阈值。
- 内置规则可复制为自定义；迁移保留既有自定义规则与默认标签开关。
- 英雄主类型来自 Riot Data Dragon 16.20.1 的第一类型，共 173 位；未知类型不补猜。

## 手动验收入口

设置 → 标签管理 → 查看任一内置标签 → 复制为自定义。
也可点击新增标签，在「从内置规则开始」选择模板，修改条件后保存。
全能高手的窗口、最低场数、类型占比、类型数量、各类不同英雄数、胜率比较符及阈值均可编辑。

## 2026-10-11 打包修正

用户报告旧的本地 0.9.2 EXE 启动时显示 localhost 拒绝连接。原因为普通 `cargo build --release` 未启用 Tauri 的 `custom-protocol`，编译成功但仍加载开发服务器地址。此前生产编译检查不足以证明 EXE 可独立运行。

正式交付必须执行 `npm run tauri build -- --no-bundle`；没有 npm 的本地环境可通过 Tauri CLI 配置覆盖，以 Node 直接执行同等前端构建步骤。不能直接交付普通 Cargo release 产物。

`build.rs` 现在对 release + 开发资源模式直接报错，防止重复生成依赖开发服务器的正式包。

修正验证：Tauri CLI 正式构建成功；普通 Cargo release 构建被新增检查按预期拒绝。对照旧 EXE 和修正版，入口引用的 JS、CSS 与 logo 的生产资源映射仅在修正版中存在。开发服务器 1420/1429 未运行，独立目录中的修正版进程正常启动，Windows 可访问性树识别出「海斗助手 Hexaram - Web 内容」。WebView 调试端口不可用，Computer Use 两次截图超时，因此未完成实际点击与持久化验收，不把进程启动等同于完整端到端通过。修正版使用单独文件名交付，避免覆盖用户正在运行的旧包。

## 2026-10-11 当前连胜／连败修正

- 仅统计同模式从最新一场正常对局开始的连续结果，遇到相反结果立即结束；窗口中更早的连续胜负不构成当前连胜／连败。
- 条件判定、`{N}` 标签数字和样本说明使用相同的按时间倒序排列的筛选窗口。原名称生成逻辑未限制到规则的最近窗口，回归测试复现了 50 场规则显示「60连胜」的问题；自定义标签的名称也改用其自身队列与窗口。
- 内置说明明确当前连续结果及中断条件。默认规则仍按模式分别判断、排除重开，至少连续 3 场，最多检查最近 50 场。
- 标签模块 28 项全部通过，包括新增的旧连续结果不命中、最近连续结果中断、50 场窗口数字、自定义规则乱序输入，以及模式隔离／重开／空历史测试。标签编辑器 3 项通过；TypeScript 类型检查通过。
- 全量 Rust 库测试：490 项通过，3 项失败，4 项跳过。失败均为未修改的 `paths.rs` 对配置文件及缓存名称仍断言旧的 Rank Analysis 名称，与本次标签逻辑无关。
- `npm run check` 因本地没有 npm 无法执行，已直接调用 Node 运行类型检查及编辑器测试。单独运行 Clippy 时，当前 Rust toolchain 未安装 Clippy，检查未能执行。Rust 全局格式检查和内置 JSON 的 Prettier 检查仍报告此前已有的格式差异；对照保留的源码副本确认相同问题已存在。
- 通过 Tauri CLI 正式生产构建（`--no-bundle`），导出独立的「海斗助手-0.9.2-当前连胜连败修正版.exe」及 SHA-256 校验文件。该产物包含本次新规则；没有替换正在运行的已安装程序，也未进行真实玩家数据的端到端验收。
